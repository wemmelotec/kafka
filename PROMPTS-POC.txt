------------------------------------------------------------

"Crie um arquivo docker-compose.yml na raiz de C:\workspace_eclipse\kafka\

ETAPA 3 - notification-service (novo projeto, Consumer)
------------------------------------------------------------
PROMPT:
"Crie um novo projeto Maven Spring Boot em
C:\workspace_eclipse\kafka\notification-service (groupId com.poc,
artifactId notification-service, Java 21, Spring Boot 3.5.0), com
estrutura hexagonal espelhando o order-service:
- domain/Notification.java (record, com factory from(OrderCreatedEvent))
- application/port/out/NotificationSender.java (interface send(Notification))
- application/port/in/OrderCreatedHandler.java (interface handle(OrderCreatedEvent))
- application/service/OrderCreatedHandlerService.java (@Service, injeta
  NotificationSender, converte o evento em Notification e envia)
- adapters/out/notification/LogNotificationSender.java (@Component, loga
  a notificacao)
- adapters/in/messaging/OrderCreatedEvent.java (DTO do evento recebido,
  com os MESMOS campos/tipos do OrderCreatedEvent do order-service:
  orderId, cpf, totalValue, occurredAt)
- adapters/in/messaging/OrderCreatedKafkaListener.java (@Component com
  @KafkaListener(topics = '${app.kafka.topic.order-created}',
  groupId = '${spring.kafka.consumer.group-id}'), delega para
  OrderCreatedHandler)
Dependencias: spring-kafka, spring-boot-starter, spring-boot-starter-test,
spring-kafka-test (test).
application.properties: spring.application.name=notification-service,
spring.kafka.bootstrap-servers=localhost:29092,
spring.kafka.consumer.group-id=notification-service,
auto-offset-reset=earliest, key-deserializer=StringDeserializer,
value-deserializer com ErrorHandlingDeserializer envolvendo
JsonDeserializer, spring.json.trusted.packages apontando para o pacote
do DTO, spring.json.value.default.type apontando para
adapters.in.messaging.OrderCreatedEvent, app.kafka.topic.order-created=
orders.created. Garanta JavaTimeModule no ObjectMapper usado pelo
JsonDeserializer para desserializar Instant corretamente."

COMO VALIDAR:
[ ] `mvn spring-boot:run` no notification-service sobe sem erros
[ ] No Kafka UI (Consumers), o group "notification-service" aparece com
    as 3 particoes atribuidas, estado Stable
[ ] Disparar um novo POST /api/orders no order-service (ver Etapa 2)
[ ] No log do notification-service aparece uma linha do tipo
    "[NOTIFICATION] Pedido <orderId> ... notificacao enviada" com o
    MESMO orderId retornado pelo POST
[ ] Nenhum erro de deserializacao (DeserializationException) aparece no log

ETAPA 7 (OPCIONAL/BACKLOG) - Melhorias futuras
------------------------------------------------------------

- Error handling/retry/DLQ no consumer (DefaultErrorHandler +
